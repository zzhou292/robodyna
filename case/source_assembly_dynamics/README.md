# Connected source assembly dynamics

`SourceAssemblyWallCase` composes the authenticated source bindings and immutable
wall setup with one TL `FENodalState`, six source rigid groups, native QEPH/T3
plastic batches, the nodal finite-mesh wall contributor and their existing
joined publication. It adds no constitutive law, mass formula, constraint
recurrence, device allocation scheme, Chrono dynamics step or independent clock.

The public case borrows nothing after startup: source/setup handles are retained
by immutable ownership. `Config` requires an explicit fixed step and deformation
envelope. It has no singular material override. Both batches receive the same
complete original source material catalog and reference inventory. All 915 parent
and 1030 node buffers use exact active sizes; the app's host payload and participant
device ceilings are preflighted. The reported host payload excludes shared
bindings/setup, participant-owned staging and allocator metadata; those modules
retain their own reported budgets. Only startup allocates mechanics/observation
storage. Output serialization and viewer allocation are separate operations.

`Step.cu` states the transaction. Accepted QEPH, T3 and wall loads assemble in
that order. The case copies the actual assembled force/couple components before
sealing, then uses the native rigid-group advance and authenticated candidate
motion/reaction/group readbacks. Both material candidates and the complete wall
result are staged and checked before `ShellBatchPublication::Commit`. That call
owns the sole nodal/history commit; only infallible host capture selection
follows. Numerical rejection retains every accepted participant. A detected CUDA
failure poisons the case; this module does not promise context recovery.

`Checks.cpp` checks all native histories and their exact source references,
material/section resultants, original curve bounds, family work reductions and
declared deformation/native-step envelopes. `ContactChecks.cpp` checks complete
parent/node/source-wall identity and the local force/potential/work certificates.
The separate `source_assembly_observation` module performs source-group kinetic
replacement and stable applied/reaction kick observations. These declared
midpoint/lagged-frame metrics are not a synchronized physical-energy balance or
a proof of nonlinear coupled timestep stability. Native TOTAL J stays
authoritative; physical/added partitions and plastic work are diagnostics and
are not counted again in total work.

Const accepted accessors are empty before initialization. Contact is empty at
epoch 0 because no completed interval exists; its first actual base assembly is
required to have zero force/potential/penetration for the certified positive gap.
Later contact diagnostics retain their `PreparedCandidate` phase alongside the
case's complete accepted stamp. All borrowed accepted views expire at the next
successful `Step` or destruction. `CaptureAccepted` delegates to the existing
full-source accepted output; it cannot advance mechanics or publish a candidate.

The owning include is `SourceAssemblyDynamics.cmake`, target
`robo_dyna_source_assembly_dynamics`. The standalone `CMakeLists.txt` needs an
explicit `ROBO_DYNA_TL_ROOT` containing authenticated `CopyPrepared`, the frozen
`ROBO_DYNA_SOURCE_ASSEMBLY_INVENTORY`, original
`ROBO_DYNA_SOURCE_ASSEMBLY_WALL`, the existing Chrono install and CUDA toolkit.
Root runs this build and CUDA gate under the workstation guard.

Five actual-source test cases cover startup and exact host/count budgets,
identity mismatch, agreement with the existing grouped free-flight fixture,
late contact/observation rejection and deterministic retry, and 256/1024 accepted
contact intervals with stable allocations and complete source output. The
smoke explicitly uses 8 m/s, a 5 micrometer initial gap and `h=1/67108864 s`;
the horizons are 3.8/15.3 microseconds. These are storage/source/transaction/contact
integration checks, not a visible full-car crash or plasticity accuracy study.
No video or admitted replay schema is generated by this module.

Qualified on the RTX 5090 in `source-assembly-dynamics-tests-1`: all five cases
pass. The 256/1024-step runs reach contact at epoch 42. At epoch 1024 the wall
resultant is 10,976.656194077337 N and maximum material-point plastic strain is
0.00070593767410028646. Participant device payload remains 7,105,388 bytes;
the complete test process peaks at 213,622,784 sampled resident bytes.
The 1024-step case takes 110.767 s including its checks and saved-output probes.
This measured throughput requires profiling before a millisecond-scale run.
The initial build exposed a missing shared wall-geometry CMake dependency,
fixed in the owning `WallTessellationLibrary.cmake`; rebuild passes.


`Config::observe_force_stage` is an explicit default-off observation option.
Enabled startup asks the existing TL owner to retain the actual native kick's
node and generated-primary A/AR. `ForceStage.cpp` reads them after the prepared
nodal/group snapshots, retains both separately returned prepared identities,
and uses the previous accepted motion with the prepared group axes in the
qualified pure `ObserveForceStage` adapter. It adds no force call or integrator
clock. `CheckForceStage` is the final candidate check before the same common
commit. These extra optional operations are included in inclusive step timing;
the existing per-operation timing schema is unchanged.

`accepted_force_stage()` is null initially and whenever the option is off. Once
a step commits it returns the completed base-time sample with its base epoch,
attempt, enclosing accepted epoch/time and full source-group descriptor. The
ordinary native, grouped native and effective aggregate channels retain their
explicit phase and count each generated primary once. They are separate from
the stored midpoint kinetic channels. No native-work/potential composition,
energy acceptance threshold or synchronized energy-balance claim is added here.
The returned pointer follows the existing accepted-view lifetime. Rejection
keeps the prior summary visible; a CUDA failure preserves that accepted record
but poisons further advancement.

The case preallocates one `6*n` double capture buffer and `g` typed source-bearing
group rows only when enabled, inside the existing explicit host byte cap. For
1030 nodes and six groups this is 49,872 additional host payload bytes and the
owner adds exactly 49,728 device bytes without another device allocation. Fixed
inline summary/identity/vector descriptors are included in `sizeof(Impl)` even
when disabled. Consequently an older archive's `engine_host_payload_bytes`
metric changes truthfully with this implementation; this is not a mechanics
change. There are no additional capture calls or dynamic capture payload when
off, and no per-step container growth when on.

The new actual-source qualification cases cover exact optional byte admission,
128 baseline intervals of enabled/disabled nodal/section/contact parity,
first/later force-stage chronology and an independent world-tensor collocation
oracle, late node/group/identity rejection with exact retry, and a completed
capture transfer followed by a CUDA error. The last case uses the existing TL
qualification-only linker probe, never a production failure hook. Its correct
outcome is a poisoned case, not retry. The 128-interval scope establishes
contact and material-history parity without asserting first yield. These new
CUDA cases now pass the root's guarded runtime qualification:
