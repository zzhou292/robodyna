# Original CIN shell witnesses

The immutable roster retains the original CIN NSV/IRECT map and the complete
349,645-parent shell binding on the same canonical backing. One source-order
node-incidence index finds every shell containing each patch's four physical
slots. QEPH, T3 and QBAT source parents stay distinct; repeated T3 slots admit
both genuine triangle witnesses and quads containing those three nodes. The
roster preserves EID, PID, canonical row, native family/index and original NIDs.
It does not replace the declared mechanical master with an INCOQ witness.

No activity is inferred. This is a sufficient shell subset of native CHK2MSR3NB;
solid-face witnesses remain outside this profile. Missing shell witnesses or
missing domain nodes remain pending. The current CIN owner accepts one to four
fully mapped witnesses per attachment; the roster records a larger result
without silently trimming it. Runtime activity comes from accepted native
histories through the separately qualified owner/publication readback.

The default startup bound stays 2 GiB. It charges the existing conservative
reference/CIN source reservations, actual native binding payload, source-order
incidence scratch, complete bounded witness arrays and a 64-byte control reserve.
Existing source reservations can include retired parsing scratch and shared
backing more than once; this is a conservative reservation, not measured RSS.
The new source module does not decode or copy canonical geometry arrays.

Author qualification: four small host functions plus source/actual-test syntax,
1 CPU and 512 MiB. The host executable links the previously qualified unchanged
native binding/domain libraries; the owning build remains the integration gate.
No original-count/native/CUDA execution was performed in the author lane.

Configure this directory with `ROBO_DYNA_TIED_CIN_WITNESS_ACTUAL=ON` for the
original gate. Supply the existing `ROBO_DYNA_VEHICLE_{CANONICAL,SCOPE,DECLARATIONS,
GLASS_RESOLUTION,GLASS_SHA256}` inputs and `ROBO_DYNA_TL_ROOT`. The two original
functions reuse the qualified classification/CIN fixture and full native shell
binding; they report actual witness count, maximum per row and unmapped slots.
They do not instantiate a full vehicle dynamics owner.
