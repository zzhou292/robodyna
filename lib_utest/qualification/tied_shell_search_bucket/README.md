# Independent native bucket traversal

This test oracle executes the complete pinned I2TRIVOX and existing complete
I2DST3/I2BAR3/I7LIN3 over supplied working coordinates and ordered IRECT/NSV/MSR.
It accepts independently qualified shell thickness inputs. Production bounds,
candidate lists and selected mappings are never oracle inputs.

The selected profile is ILEV28 / IGNORE2 / DSEARCH0, with zero secondary shell
incidence and an already resolved shell match for every master. App geometry
qualification independently checks every original match and every permutation
of the coincident glass/midlayer sets against complete INCOQ3 and both consumed
thickness callers. The original 193,068 packets all agree. This separate proof
permits an explicit supplied-thickness I2COR3 adaptation here: no INSOL3 result
is consumed by either caller when the qualified shell match exists. Unused
element/material arguments are opaque storage and are never represented as a
complete vehicle solid or shell incidence inventory. This is not complete
I2BUC1 or I2COR3 execution.

Domain.F retains exact I2BUC1 diagonal, influence, MSR-extrema and cell-count
fragments, including the second DD update's literal reuse of diagonal13.
Coordinates.F retains exact I2COR3 secondary coordinates, MIN-diagonal gap and
master coordinates; it logs the actual native pairs at that call seam. Complete
I2TRIVOX still owns buckets, candidate traversal, physical-own-node exclusion,
inclusive box tests and batching. Complete I2DST3 owns projection and ordered
selection. No production math participates in the native enumeration.

Fresh unmatched choices use zero indices/S/T and DBL_MAX distance, matching the
existing qualification packet; no native finalization or starter classification
is implied. Unmatched results remain present. I2TID3 compaction/DMIN clearing and
constraint classification are separate later gates.

The packet is serial. Small test context modules supply only allocation and an
unconsumed stack field. Complete shared precision, element dimensions, constants,
hardware and MVSIZ are reused from existing authenticated donors. ILEV27 has an
abort-only uncalled symbol; it cannot silently substitute the selected routine.
Source verification authenticates reused files and exact new byte slices.

Counts, finite values, indices, master coverage, unique source node lists and
native domain/cell capacity are checked. Caller outputs are staged through the
entire call, including pair overflow. The logger uses a 64-bit count; only a
successful bounded result is narrowed. No per-pair truncation is published.
Limits are 1,048,576 nodes, 524,288 masters, 65,536 secondaries, 8,388,608 pairs
and 1,000,000 cells, subject to the owning process memory guard. A zero native
DD has no defined cell scale in this profile and is explicitly rejected.

Four small native functions pass, including more than one native MVSIZ batch,
true triangles, coincident but distinct node sets, physical-own-node exclusion,
unmatched rows, exact pair coverage and choices against an independent exhaustive
native small fixture, capacity failure/retry and an asymmetric diagonal control.
All 11 existing native search regressions and shared source identity pass in
`tied-bucket-root-tests-1`. These are small fixtures; complete original bucket
execution and comparison with the production GPU driver remain owning gates.
Configure1 failed only because the fragment verifier requires its reused sources
listed in the local manifest; configure2 corrected that metadata. Build1 found a
C++ test-helper name collision with GTest::Run; build2 renamed the helper. No
donor arithmetic or tolerance changed.

Use the standalone CMake directory with the existing explicit Fortran compiler.
Consumers include Native.cmake and link tied_search_bucket_native; tests can
also reuse tied_search_oracle. Root serializes all builds and full-source runs
through the workstation guard. No production runtime or GPU driver is added by
this oracle.
