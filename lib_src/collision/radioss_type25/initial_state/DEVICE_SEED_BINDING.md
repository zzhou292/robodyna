# Typed GPU initial state and runtime binding

Reviewed architecture, source implementation in progress. Root approved the
internal invocation boundary on2026-09-26. The new private pair/winner headers
are only its value layer and remain unqualified. No public Transaction fields
have changed.

`InitialSourceView` will carry independent N/NS/P/G/R counts, explicit initial
phase/INACTI5/IGAP1/IVIS2/ISHARP/IRESP/NSPMD controls, source ID/generation,
physical-source identity and actual global/local maps. It borrows genuine final
mixed Startup normals/references and source working coordinates, coefficients,
gaps, NSV/MSR, roles and post-GAPM support metadata. Physical parent/support/raw
surface origin remain separate identities. Native coordinates must retain the
source bits and prove the existing native×length→owner SI correspondence; an
unproven inverse reconstruction from rounded SI is not source authority.

Removal input has a distinct **before final TYPE2 augmentation** geometric CSR,
the actual ordered finalized TYPE2 roster, native used/allocation counts and
resolved removal controls. A final CSR alone cannot replace that earlier phase:
Starter selects first, then REMN may clear the winner. Existing typed augmentation
builds the authentic final CSR. Its numerical row reset is reproduced on device
from the exact addition count and literal positive global-main comparison; no
absolute-value marker, blanket slave removal or guessed membership is allowed.
No-additions preserves the row. Mixed G=P+S extension is explicit, never2P.

`Forecast(source,limits)` will check typed host spans/counts/phase/coherence and
compute all simultaneous resident/staging costs without launching physics.
`Prepare(source,limits,stream,DeviceSeed&)` will build a move-only opaque seed
with private GPU history/ICONT buffers and small source/count/generation/warm/
reset diagnostics, including separate warm positive/zero/negative main-STF
counts. Warm rows are retained literally; a source census does not authorize
unqualified negative-coefficient runtime continuation. Device views are unavailable until complete successful
count/admission/numerical status folds. Host readback is only bounded diagnostics
or owning qualification. The source-sized path has no host per-pair loop.

The pipeline reuses existing GPU x-sort/range/task/count/scan infrastructure with
literal Starter pair filtering. It emits complete bounded pairs, evaluates the
shared initial leaves, builds per-secondary incidence and uses one writer per
row for native nearest-distance/larger-global-main selection. PWR5, chronological
tied normalization and PREPARE_INT25 follow in separate kernel stages. Temporary
nearest-distance values are discarded, not installed as runtime TIME_S. Original
I25CAND's symmetric startup-candidate handoff will be checked against Engine's
first rebuild/Begin before the runtime source option is opened.

For native Transaction initialization, the producer consumes the already
validated and copied immutable SourceStaging on the actual owner's stream. This
keeps source↔seed equivalence structural, rather than trusting an externally
supplied row buffer or matching only a caller-chosen ID. After complete producer
success, private D2D copies initialize both existing history/flag slabs. Each
slab gets the existing source keys and epoch0 selector contract. The producer's
scratch and temporary immutable seed retire only after those copies drain.
Failure leaves the transaction unavailable and all previously published owner
state untouched. There is no second clock, permanent host row mirror or new mass
owner. Source preparation owns copied buffers through the initial drain; borrowed
caller buffers may then be released. Legacy cold initialization remains separate.

The forecast includes source upload or genuine borrowed owner views, x keys/order,
range/task/pair counts and scans, emitted pair values, row incidence, per-row
winner, final CSR where newly built, temporary seed, and D2D overlap with both
existing history slabs. Reuse scratch only after explicit stream barriers and
retirement. Alias/cap/overflow/wrong phase/foreign map or stamp rejection is
required before publication. Host fenv admission remains at the host entrypoint;
raw HOST_DEVICE leaves qualify fixed arithmetic through strict native tests.

Owning gates must first compare whole original COR3/PEN3/PWR3 and literal final
mapping with same-input native bits, including T3 repeated boundary visits,
zero-bisector behavior, true distance ties, warm/cold/solid/coating cases and
positive-only/no-addition tied reset. Then GPU launch/order/staging/cap/retry and
wrong-source binding gates must pass before actual retained-V5 source-sized warm
counts or a matched physical prefix is admitted. Captured original-full rows are
expected evidence only and cannot enter these source factories.

`CHECK_SURFACE_STATE` is not a blanket initial absolute-value operation: its
negative flip uses the saved deactivated-surface roster/NB_CONNECTED_ELM1 path.
All-active physical state does not prove warm main K is positive. Until the
explicit native runtime continuation profile qualifies a reachable negative warm
row, initialization must fail with a truthful warm-sign diagnostic rather than
resetting markers, clipping coefficients or silently pruning source geometry.
