# TYPE13 resident force and history contributor

`Batch` owns one complete immutable TYPE13 model through its existing
`Type13NodeContributions` handle. Its native H1 properties remain compact owned
values with four five-point curves and six history channels. The declared
`NodalNodeDomain` maps only the two physical endpoints; N3 retains reference
identity and receives no force, mass or inertia.

The batch allocates one checked device arena with two complete `Evaluation`
slabs. Accepted force, current native stiffness, signed work, activity, curve
positions and other histories use the same selector. Candidate evaluation uses
the actual owner's prepared position and midpoint velocity/spin. Source-ordered
status reduction identifies the first failing connection. Every public read
stages and checks the complete result before changing any caller output.

## Startup, units and coefficient boundary

Startup calls the qualified `InitializeForce` on original working-coordinate
bits at native TT0/DT0. First assembly checks represented SI endpoint positions,
declared common velocity, zero spin and valid nodal orientation against the
actual owner's authenticated sources. Subsequent owner positions are divided
by the explicit length unit; velocity is multiplied by time/length and spin by
time. The independent native oracle receives exactly these later packets.
Tests retain an explicit negative control showing that an SI round trip changes
some source coordinate bits and must not replace raw TT0 coordinates.

This contributor constructs no inverse coefficients and never requires positive
inverse mass/inertia on CIN dependents. Its ordinary profile adds native force
and couple caches. The explicit `CinNativeStiffness` profile obtains the owner's
actual CIN destination using its attempt token and also adds STI/STIR there.
An actual CIN owner rejects the ordinary profile before any TYPE13 scatter,
so selecting it cannot silently omit stiffness.
For the admitted zero-damping profile, complete native R2LEN3 gives the pre-floor
XKM/XKR at each active endpoint. Current OFF0 gives zero STI/STIR even on the
failure interval that still carries force. Native positive DT remains separate.

The current qualification excludes rigid-member endpoints through the actual
owner membership query. This affects zero original TYPE13 endpoints: original
source receipt `cin-master-role-root-tests-2`, function XML
`cin-master-role-root-functions-2`, on app `3837760`, proves no rigid PART/plain/
auxiliary-group intersections for any of the 11,165 selected secondaries,
including all 7,493 TYPE13 endpoint nodes. The immutable domain/source identity
and runtime membership check remain necessary for every different model; that
census is not a global absence assumption.

The isolated trajectory supplies ordered native endpoint M/J for a specifically
qualified beam-only owner. Total native J already includes added J and is added
once. Full production composition still must authenticate the complete physical
coefficient ledger, mapped shell/solid/rigid contributors and owner. A successful
beam trajectory does not establish those other producers or vehicle coverage.

## Publication and resource accounting

There is no production TYPE13-only commit API. Private publication preflight
and infallible `Publish` are reserved for the existing `ShellBatchPublication`
coordinator. The owning tests define a test-only peer: preflight, complete case
receipt, sole `FENodalState::Commit`, then the host slab switch. A late failure
discards both candidates. No allocation or CUDA work follows owner commit.
Combined production publication for mapped participants is a subsequent gate.

Default explicit bounds are 8,192 connections, 1,024 properties, 524,288 domain
nodes, 32 MiB device payload and 256 MiB simultaneous host payload. Arrays use
actual counts. `Batch::Forecast` charges the retained immutable source/domain
once through its owning handle, `Batch`/`Impl`, the complete startup arena, and
the reusable readback staging before optional allocation. It preserves output on
failure and supports exact-byte retry. It reports payload reservations, not
allocator metadata, CUDA-driver memory or process RSS. After startup the upload
arena is released; there is no per-attempt growth.

The measured 4,442-parent/one-property arena is 7,410,768 bytes; its complete
readback slab is 3,198,240 bytes. The maximum 8,192-parent/1,024-property arena
is 14,639,664 bytes. These source-sized layouts require no source execution.
The root-only original test reports the complete
retained-source forecast before startup and verifies all 4,442 native packets.

## Qualification ownership

`lib_utest/qualification/type13_resident` owns the host/native/CUDA tests. Native
force/history reuses `type13_recurrence/NativeOracle` and its existing exact
R4DEF3/REDEF3/VINTER2/frame/scatter wrappers. Only the complete R2LEN3 endpoint
loop is newly extracted, from the already retained pinned donor. No original
fixture or native force formula is copied into the resident implementation.
Its source manifest and shared donor identities are independently checked.

The authored gates cover loaded mixed active/failed histories, removal and two
continuing intervals, late contributor and final-element rejection, exact
accepted-state retry, readback corruption, initial/byte caps, real CIN stiffness
with zero dependent inverses, and every original beam in an eight-interval
actual-owner/native force-history comparison. They establish this contributor's
recurrence on actual owner packets, not a second complete native nodal solver.
