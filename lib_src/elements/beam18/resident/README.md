# Mapped beam18 resident

This participant retains `beam18::Model` and the qualified circular four-point,
tabulated LAW44 force recurrence. It owns one device arena with uploaded owned
curves, references, two complete history/cache slabs and bounded validation
storage. `InitializeJoined` constructs native TT0 values without beginning an
owner trial. The model's orientation-only N3 never becomes a mechanical endpoint.

Before any assembly, the common publisher must authenticate the actual V5
ledger, the identical model/domain, the complete PART/plain rigid binding and
the initial raw CIN coefficients. The existing physical-owner proof and actual
owner queries perform this check. Ordinary and rigid-member endpoints both need
active rotational DOFs; dependent zero conventional inverses are valid. An
unclaimed allocation-only batch cannot assemble, evaluate or expose accepted
physical-run diagnostics.

Accepted RHS forces/couples and native scalar STI/STIR are added in model-parent,
then endpoint order. Existing accumulator values are preserved. Stiffness uses
the actual CIN destination, not generic free-node bounds. The existing owner
chooses and advances the interval; candidate evaluation gathers its complete
prepared endpoint position, velocity and angular velocity. No second clock,
nodal update, mass scaling or topology inference is implemented here.

Every candidate has a complete qualified force/history cache. Diagnostics use
deterministic parent-order sums of the two native internal-work increments,
plastic-work increment and RHS-signed kick/drift observations, plus the minimum
native unscaled timestep. These observations do not change the owner's timestep
or certify a full-case energy balance. Failure leaves accepted storage unchanged;
discard permits a new owner attempt. Publication requires the exact claimant and
prepared owner/source/phase identity. Only the common publisher commits the owner,
then invokes the infallible slab swap.

The force/history cache contains borrowed **device** curve addresses internally.
Readback validates those exact relocated identities without dereferencing them on
the host, then publishes pointer-free `Result` values only after every parent
succeeds. Counts, alignment, source/output aliases and late invalid fields reject
before user output changes.

## Common publisher integration boundary

This slice deliberately does not edit the common publisher or app runtime.
Integration must add an optional retained beam model and `beam18::Batch` to the
existing complete physical source profile and shared participant roster:

1. Construct from the same V5 beam model/ledger/rigid/CIN authorities; include
   `Batch::Forecast` in the existing complete host/device phase forecast.
2. Preflight every participant's initial attach, allocations and readbacks before
   any private `AttachPublication`. The actual publisher is the claimant passed
   to this batch's private attach/preflight/release operations.
3. Assemble the accepted beam contribution before existing Seal/CIN advance;
   evaluate it against the same prepared owner view. Include its diagnostics in
   the existing prepared/accepted roster and output-range protection.
4. Preflight **all** participants before the sole owner commit; call beam Publish
   only afterward. Release/poison/discard must include this participant.
5. Existing solid and shell publication source guards must explicitly admit V5
   after checking the same retained authorities. Preserve all old no-beam entry
   points and source restrictions. V5 itself permits V3 or V4 solids; the actual
   vehicle profile decides which complete retained source inventory is required.

Plain rigid groups consuming beam native-total inertia use the separately
qualified `InitializeNativeTotal` API. Its unpartitioned channel comes directly
from the beam ledger partition. The beam producer supplies no fabricated
physical/added split, and this resident does not manufacture one.
