# Extended resident solid contributor

`PhysicalCinExtendedLaw44Law90V2` pairs only with the immutable
`ExtendedLaw44Law90` model and its exact V4 physical ledger. The old
`PhysicalCinV1` path remains paired with the original three-family model.
The sole existing common publisher authenticates actual owner, rigid binding,
CIN receipt and exact model before claiming any participant. One owner commit
precedes the infallible shared accepted/trial slab swap.

The family order is 18,24,6z,44,90. Rear LAW44 uses the already-qualified external
TT0/interval scratch and retains all eight source slots, including both collapsed
pairs. Its force and positive STI additions use the existing ordered repeated-slot
utilities. LAW90 uses its qualified external scratch; immutable material curves
are copied once and rebased with `RelocatePreparedCurve`. The helper preserves all
prepared scalars and loading flags without reading opaque destination storage or
re-running preparation on GPU. Host readback checks expected device addresses,
full named history/state and five-family diagnostics before publishing caller
outputs. Solids write neither couples nor rotational stiffness.

Scratch is `min(parent_count,4096)` per qualifying family, matching existing
64x64 candidate workers. Typed headers, status arrays, two state slabs, material
curves, scratch, complete staging and actual initial-owner proof are counted by
the same arena/forecast. Default 128MiB device/256MiB host limits are unchanged.
The count-only host forecast uses 372435 nodes and the qualified 4063 original
family counts; the actual constructor gate records exact material/source budgets.

Host controls cover both LAW90 loading branches, curve relocation extents and
alias rejection, destroyed borrowed contents, exact caps, last-family count
rejection, typed recurrence and output-preserving retry. The actual owner fixture
reuses the established PART/plain/CIN source, builds its genuine V4 ledger and
compares every prepared rear/foam exported history against independently carried
complete native donors with their unchanged owning tolerances. The host force
call supplies only unretained point/geometry fields to the existing comparators;
every resident-exported field replaces the corresponding host value first.
Seeded STI, couples and STIR prove original-slot addition and untouched rotations.
Later contributor rejection and deliberately corrupted final LAW90 cache readback
leave accepted history/owner state unchanged and permit complete retry.

The optional original gate uploads all 4063 old+rear+foam parents and checks all 306
rear plus 1345 original blank-HU/IFLAG1 foam constructors against native. Rear
material selection uses the owning corrected PID helper (2000016:50GPa;
2000392:200GPa). Foam explicitly uses the authenticated native SDI density and
raw-MPa/YFAC1e6 material receipt alongside unchanged canonical source geometry.
This is constructor qualification, not complete 4900-source vehicle integration
or a full vehicle trajectory. The latter remains the app source/owner gate.

## Root gate

```sh
cmake -S lib_utest/qualification/extended_solid_resident \
  -B /ABS/crash-work/build/extended-solid-resident-root-1 \
  -DTL_EXTENDED_SOLID_RESIDENT_CUDA=ON \
  -DTL_EXTENDED_SOLID_RESIDENT_ORIGINAL=ON \
  -DREAR18_SOURCE_FIXTURE=/ABS/crash-work/reports/yaris-rear-metal-geometry-1 \
  -DTL_LAW90_RADIATOR_FIXTURE=/ABS/crash-work/reports/yaris-radiator-geometry-1 \
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=120
cmake --build /ABS/crash-work/build/extended-solid-resident-root-1 --parallel 2 \
  --target extended_solid_resident_host extended_solid_resident_legacy extended_solid_resident_cuda
ctest --test-dir /ABS/crash-work/build/extended-solid-resident-root-1 \
  --output-on-failure -R 'extended_solid_resident|native_identity'
```
