# Fresh compact QEPH mixed-section activity

Only the mapped QEPH parent-activity path changes. Every query still authenticates
its actual owner/source/stamp and reads the current selected device slab. The
ordered phases remain mixed sections, failure history, complete force cache,
then source-parent role/activity agreement. Full section, failure and force
readback APIs remain unchanged; they still copy and construct their complete
typed histories.

This applies uniformly to every count and law/role combination already admitted
by mapped QEPH, in accepted and prepared phases. It adds no model-specific count,
constant-activity assumption or new source profile. Existing source admission,
error priority and public full-history contracts remain the authority.

The mixed phase uses the existing FiniteSection predicates. Their only source
adaptations are host/device annotation and a local const array in place of the
diagnostic initializer-list, preserving every scalar and evaluation order.
Elastic rows check their actual fifteen stresses; plastic rows check all history
and diagnostic values; rigid skins expose no material points. Unselected private
capacity remains unread. Negative finite fields remain admitted where the old
predicate admitted them. QEPH one-point roles remain unavailable.

Each worker emits a role byte only after its selected payload passes. Integer
parent-first status retains the original elastic/plastic error message and unset
public parent index. Fresh source availability checks use the immutable retained
catalog. Uploaded laws come from that same admitted source, as in the qualified
force/failure path; this does not claim detection of arbitrary external mutation
of private immutable model memory. The old reader itself manufactured each host
union tag from this catalog. The activity path therefore needs the validated role
byte, not an entire manufactured union. Final agreement still checks that byte
against the current retained source and compares force/failure flags in parent
order. Malformed compact role encodings reject before later phases; a valid but
wrong role retains the original final role phase, after complete force checks.

The existing device packet is reused mixed -> failure -> force, with each D2H
copy synchronized before reuse. One new startup-sized host role packet remains
alive through final agreement. Its entire range is alias-checked and forecasted,
including its 64-byte control reservation and actual larger Impl size. It adds
no device allocation, accepted-state selector, clock or retained validity cache.
All public outputs remain staged until success. Runtime failure poisons the batch;
prepared failure discards the candidate and retry validates fresh data.

At 324094 QEPH parents, activity D2H falls from 114729284 to 972294 bytes/query:
three 324098-byte compact packets, three copies and three synchronization phases.
The additional host buffer/control costs 324162 bytes, plus actual Impl sizing.
The actual V5 witness +wall accepted +wall prepared call chain has three queries
per integration step. Keeping T3/QBAT unchanged, its payload falls from 562075356
to 220804386 bytes/step, saving 341270970 bytes. These are exact payload counts,
not PCIe transaction overhead or measured speedup. Historical mixed copy/finite/
packing cost was about 31.2 ms/query; current timing remains a root gate.

The complete old mixed reader and FiniteSection helpers are frozen in this
qualifier. Their executable host oracle substitutes only transport/source-query
seams and namespace/include decoration. The source verifier checks the unchanged
full reader and the exact mechanical helper transformation. Ten host functions
include 230 selected-field/role cases, all byte encodings, ordered role agreement,
and existing inclusive capacity tests. Four new CUDA functions add all roles,
earlier/late failures, ignored private capacity, mixed/failure/force/role priority,
packet corruption, aliases, poisoning and discard/retry; existing loaded owner
and full-history comparisons remain. CUDA and full-V5 archive/timing gates are
root-owned; author checks are one CPU/512 MiB host and syntax only.
