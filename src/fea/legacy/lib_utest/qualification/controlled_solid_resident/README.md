# Source-controlled solid resident gate

The existing solid Batch owns both legacy and SourceDeclared H24/LAW90 controls under the same accepted/trial slabs, common owner publication and SI clock. `PhysicalCinSourceControlsV3` requires complete native packet membership, at most 128 rows per packet, and exact SI or mm/Mg/s units. S6 controls remain unsupported. Cross-packet execution does not reproduce native OpenMP arrival order; within-packet membership and integer damping OR are authenticated.

Four 128-lane blocks reuse a bounded explicit workspace pool. Every lane reaches every packet barrier, including failed rows. Tagged histories retain native material/hourglass/distortion values; force, stiffness and work caches use SI. `CopyAcceptedResultsWithControls` / `CopyPreparedResultsWithControls` expose pointer-free numeric histories with unit stamps. Legacy readback rejects controlled models. Distortion work remains separate from material and hourglass work.

The gate covers five host admission/layout tests, twenty-one retained host regressions (eight extended and thirteen legacy) and five actual CUDA tests: SI/mm and distinct/collapsed H24 through four owner commits; failed publication and whole-output readback rollback; exact budget retry; a real anisotropic zero-mean buckled row coupled to a triggering row in the same native packet, including failed-lane barriers; and seeded collapsed assembly through gather, serial and forced fallback. Packet zero H24 and packet four LAW90 reuse one block/workspace, exercising both union transitions. Element operators inherit their independent native gates; this integration fixture uses host operators as the scheduling oracle. It is not a full-vehicle stability or timing result, nor a claim of long carried LAW90 trajectory equality.

The SM120 packet kernel uses 255 registers, a 11,296-byte stack frame and 1,028 shared bytes. The maximum 512 launched lanes imply 5,783,552 bytes of logical live frames, separately from the exact explicit arena. CUDA-managed allocation can differ; bounded GPU growth measurements remain required. The standalone workspace upper bound is `512*sizeof(controlled::Workspace)` (currently about 17.2 MiB), not a per-parent force scratch allocation.

Configure this directory with CUDA architecture 120 and strict floating-point options retained by the targets. The new source manifest pins this profile and the reused operator sources; the older extended-profile manifest is preserved and checked by its own default gate.

The optional `SourceControlledBatchLimits()` requests a192 MiB device ceiling forV3 only; the default and every legacy hard ceiling stay128 MiB, and host limits stay256 MiB. It changes admission only, not any arena region, layout order, worker count or physics. The complete bound-model count shape already needs135,692,792 bytes before curves; each curve point adds16 bytes. Even the full allowed1,048,576-point curve pool fits152,470,008 bytes. The exact host startup forecast remains authoritative and unchanged.

The worker-budget candidate adds `BatchLimits.max_controlled_packet_blocks` (4/8/16/32, default8). Callers may explicitly request controlled V3 component caps up to256 MiB device and384 MiB host; `SourceControlledBatchLimits()` still defaults to192/256. Legacy hard/default limits remain128/256. One shared resolver tests the requested count and smaller powers of two down to4 against the exact device layout AND complete startup host cost, and Initialization consumes that same resolved plan. Forecast and accepted/prepared diagnostics expose admitted blocks and worker slots. Requests above8 avoid block counts beyond the highest enabled packet index; default8 is preserved. Outer application/guard admission remains independent and uses the maximum of actual phases.

The32-packet-per-family fixture exercises all4/8/16/32 queue arrangements, native-unit carried histories, budget fallback and constructor/forecast agreement. Numerical snapshots compare all physical diagnostics, while owner IDs and separately asserted resource choices are intentionally distinct between independent live owners. Kernel occupancy and compiler resource attributes are recorded; they do not establish whole-vehicle timing.
