# Native TYPE25 coefficient values

This module implements source-derived arithmetic, not material resolution, geometry lookup, an incident-roster reduction, or a contact owner. Source-only authoring does not qualify a new vehicle profile or a performance gain.

The shared native/SI leaves cover ordinary Q4/T3 PM20 shell stiffness and its element/property thickness precedence; exterior solid area/volume/fill/bulk stiffness with ICONTR selecting PM107 and the native 10/16-node corrections; ASSTIFI normalization from authentic accumulated inputs including existing STIFINT; I25STSECND positive/default scaling and exact zero-removal retention; and the observed IGSTI4 min/abs/clamp with mass/timestep augmentation disabled. The solid length output is GAP_N(1), not the contact gap GAP_M. Nothing halves stiffness or adds a new contact law.

ASSTIFI receives global physical-model VOLNOD, pressure-times-volume BVOLNOD, ETNOD and NSHNOD. It returns normalized pressure BVOLNOD separately from final stiffness. Beams and other earlier contributions must be supplied through existing STIFINT; missing contributors are not silently zero-filled. The fractional-power operation remains native `pow(2*volume, THIRD)` rather than a replacement cube-root algorithm. Native EM30 is a volume floor here. SI adapters convert inputs into native units before applying floors, then convert each output according to its own dimensions. Conversions that erase a nonzero thickness/activity selector are rejected.

Unsupported coating, internal-face averaging/sign markers, stack/property-material branches, negative prescribed main scale, and unresolved material/face layouts reject without modifying outputs. Global ICONTR once-per-node corrections, full model incidence and physical source binding remain later integration work. In the pinned native T3 path, IGMAT is not freshly assigned before its special-property checks; a source owner must resolve the actual executed ordinary branch rather than infer it from a freshly read property slot. The pure ordinary PM20 leaf and its oracle do not claim to resolve that source issue.

The independent Fortran oracle compiles original selected I25GAPM expressions, the complete ASSTIFI loop, I25STSECND, and COR3 IGSTI4/clamp blocks. Authentic area and volume are supplied operands; INSOL3D and VOLINT are not replaced by fake geometry. Existing normal constants and source validation are reused. The captured 2800/2410 N/mm row supports only the pair min/clamp regression: no Young's modulus, thickness, material or incidence is inferred from those outputs.

The 110-packet corpus covers selectors, ordinary property branches, four solid layouts, ICONTR alternatives, zero fill, nodal volume floor boundaries, existing contributions, exact zero masks, default scales and pair clamps. Host tests add unsupported/nonfinite failure preservation and independent dimensional expectations. CUDA runs the same full native/SI corpus under different scheduling orders, then an overflow-times-zero rejection/retry case. Native/CUDA scalar comparison allows 64 machine epsilons for the source fractional power and library rounding; status/selector/zero-mask decisions have no tolerance. Exact signed zeros are separately checked where they control or retain native state. This is not a physical-vehicle parity claim.

Configure this directory in Release with GNU C++/Fortran, `TYPE25_COEFFICIENTS_CUDA=ON`, NVIDIA CUDA and the qualified target architecture. Owning targets are `type25_coefficients_host`, `type25_coefficients_consumer`, and `type25_coefficients_cuda`; CTest also reruns pinned source generation. The public interface inherits normal-response precision flags. Its standalone consumer links no Fortran, CUDA runtime or physical owner. Bazel `header` and `source` targets cover package closure and donor validation. Execute all numerical gates only through the workstation guard.
