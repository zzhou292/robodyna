# Accepted-owner mass runtime gate

This source slice adds explicit `ResponseMassPolicy::AcceptedOwnerCoefficients`
to the existing native TYPE25 transaction. It retains one nodal owner, publisher,
clock and raw-M storage. Static physical mass remains the default. The common
publisher's authenticated physical roster and complete CIN witnesses stay the
startup authority; no broad vehicle profile is granted.

The bounded owning tests add three host groups, five owner/value CUDA groups,
and one complete native pipeline CUDA group. The host gate checks the default
policy and omitted native mass arena/vector, unknown-policy rejection, exact
native/SI scalar bits (including signed zero), overflow/underflow preservation,
and complete repeated/zero-weight main-slot consumption. The numerical pipeline
compares complete original lifecycle/history/FOR3/ASS0 outputs across three mass
scales and zero MSI. These are numerical packets, not an assertion that a tied
secondary survives native TYPE25 removal.

The owner tests use real mapped QEPH/T3 contributions and common publication:

- Static/default versus accepted-owner mass produce identical complete response
  fields and physical commits in the existing force-active seven-node coupon.
- A genuine declared CIN attachment transfers a secondary's mass into its actual
  Q4 masters. That secondary is omitted from this test's declared TYPE25 roster.
  Three commits and discard/retry retain the proper accepted mass/force phases.
- An omitted mapped Q4 contribution leaves its genuine witness missing; contact
  cannot repair it or publish a commit. A fully assembled retry succeeds.
- A genuine PART aggregate owns the physical T3 members. Their original raw mass
  is used through contact/commits, while the default static policy still rejects
  rigid groups. No generated primary is inserted into the contact node domain.
- Device per-load conversion rejects invalid/underflowing operands without
  changing the affected outputs, and preserves signed-zero bits.

The source initializer and existing owner still exclude other element families,
additional mass producers, erosion/release, virtual nodes, rigid/CIN overlap and
unsupported native worker/response controls. Qualified CIN intrinsic numerical
mass is allowed; it is not a target mass-scaling mechanism. Host `sizeof` forecasts
include the appended policy metadata; static device regions and numerical
operations remain unchanged.
