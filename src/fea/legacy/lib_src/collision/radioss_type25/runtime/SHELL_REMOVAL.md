# Declared shell removal in native contact

Implementation in progress; the full vehicle profile is not qualified yet.

`NoDeclaredFailure` and `AllActivePrefix` retain their existing contracts.
`ShellRemoval` requires a complete physical ledger, accepted-owner coefficients,
ITHK0, explicit source deletion controls and the actual bound TYPE45 model.
The application must authenticate the executed source population and controls.

The existing startup `Plan` builds `activity_source::Plan` from the exact contact
source it validates, rather than trusting a caller-supplied relation with only
matching counts. The bounded GPU operand owner uploads those relations. The CPU
incidence and emission arrays are then destroyed with startup staging.

Each transaction owns a `PhysicalActivitySnapshot` observer. It authenticates
both accepted and prepared material activity against the common physical owner.
Separate interface observers avoid sharing a cached proof across public calls;
their extra scans and storage are explicit, not claimed to be free.

`ActivityRuntime.cpp` performs the integration:

1. Capture/authenticate accepted activity; epoch zero must be wholly active.
2. Rebind lifecycle mains, search stiffness, normal topology and free boundaries
   from the common publisher's accepted source slot.
3. Run the existing force/history stages at accepted X_n. A search reference from
   another source content generation is rebuilt before it can be consumed.
4. Capture/authenticate prepared activity. If no shell was removed, keep the
   accepted source selector without running source projection.
5. Project actual removals into the alternate source buffers. Preserve native
   connected-count event multiplicity, shared-element support, per-interface
   secondary policy and incoming neighbor cleanup. Unsupported solid exposure
   remains a prepublication failure.
6. Copy only secondary coefficients into the existing candidate-history slab;
   initial-contact flags and native friction/history channels are preserved.
7. Stage the source slot/content generation through the existing publication
   participant. Only common physical commit publishes it. Publication remains
   infallible host selector stores, with no device work or callbacks.

The first next-force step consumes the newly accepted coefficients and existing
native deleted-main/history branches. It does not erase the preceding accepted
force. A source counter change is a real content change, even if its visible
coefficient is unchanged; conservatively rebuilding search on that rare event
is permitted. Snapshot receipt generation is independent of source content.

The physical owner, masses, nodes, material laws, rigid groups, CIN transfer,
time step and structural limits are unchanged. General solid exposure and CIN
release are separate capabilities with their existing guards. Visualization
archives remain accepted output, not physical restart state.

Resource forecasts charge both source slots, complete incidence/emission maps,
normal/free-boundary capacity, counters, scan workspace and each observer. The
initial free roster copy uses its actual count even though dynamic capacity
covers every main. No runtime allocations or host mesh copies are introduced.

Required qualification includes native value parity, actual material-triggered
removal and subsequent contact steps, self+wall commit/rollback/retry, unchanged
no-removal results, exact resource admission and source-authenticated vehicle
preflight. Passing selector or snapshot tests alone does not qualify this profile.
