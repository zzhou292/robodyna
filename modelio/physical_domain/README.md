# Retained Yaris physical source domain

`VehiclePhysicalDomain` selects one explicit source domain for the complete
retained-shell demo. It reuses `PhysicalScope`, the canonical coordinate checker
and TL's immutable node domain and PART topology. It preserves every retained
shell, required solid, TYPE13/TYPE25 endpoint and original PART member. Plain
rigid groups intersecting those nodes also retain their original point masses.

Each original plain group has an ordered complete, restricted or omitted
disposition. Restricted groups receive a separate case node-set identity while
retaining the original group association and every excluded NID. PART members,
extra nodes and source-directed merges remain exact. No source coefficient,
inertia, constraint recurrence or connected-component claim is synthesized.
The omitted non-shell mechanics and released interfaces still need a case
load-path report before this selection admits an executable vehicle.

The original-source gate retains372435 nodes,753 plain groups (727 complete and
26 restricted),7372 plain members and148 original point-mass cards. All22 PARTs,
20 roots and5452 PART members remain. The six omitted groups and87 excluded
member occurrences in restricted groups stay accessible through the immutable
selection and its retained source. The existing TYPE25 and point-mass adapters
consume this exact domain, qualifying all2828 welds and148 mass cards together.

The inclusive source forecast is478651456 bytes, with17877112 bytes owned by
the TL domain and192312 bytes by the case PART topology. The default512 MiB
source cap,32 MiB domain cap and8 MiB topology cap cover construction; they do
not forecast a complete solver owner or archive.

Three value tests and two original-source tests pass in
`vehicle-physical-domain-root-tests-1`. They check source order, explicit cuts,
generated-ID collisions, singleton rejection, exact canonical membership,
unmodified PART topology, joint weld/mass mapping, exact allocation boundaries
and failure without replacing an existing immutable result.


The explicit native V6 support-source policy preserves the V5 physical node,
rigid group, point-mass, structural-beam and joint populations while binding
`NativeConvertedSupportsV6` solid references (raw8 HEPH aliases). Shared
`HasVehicleSupports` predicates centralize complete-support admission. V5 stays
explicit and unchanged; mismatched V5/V6 source/domain/joint policy combinations
are rejected. This layer does not enable mechanics, a runtime owner or CLI mode.
